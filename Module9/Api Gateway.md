# API Gateway: Единая Точка Входа для Микросервисов Книжного Магазина

## Введение

В современной микросервисной архитектуре, где система состоит из множества независимых сервисов, возникает важная
проблема: как управлять взаимодействием клиентов с этими сервисами? В нашей архитектуре книжного магазина уже существуют
четыре сервиса: User Service, Order Service, Book Service и Author Service. Клиенту приходится знать адреса всех этих
сервисов, что создает сложности при масштабировании, изменении API и обеспечении безопасности. Решением этой проблемы
становится внедрение API Gateway — единой точки входа во всю систему.

## Что такое API Gateway?

API Gateway — это архитектурный паттерн, который представляет собой единый интерфейс для доступа к набору микросервисов.
Вместо того чтобы обращаться напрямую к каждому сервису, клиенты взаимодействуют только с Gateway, который
перенаправляет запросы соответствующим сервисам. Это похоже на ресепшн в отеле: вместо того чтобы искать каждый отдел
самостоятельно, гости обращаются к администратору, который знает, куда их направить.

## Маршрутизация запросов

API Gateway будет анализировать входящие запросы и маршрутизировать их на основе пути запроса:

    /api/auth/ → User Service (аутентификация и регистрация)

    /api/orders/ → Order Service (управление заказами)

    /api/books/ → Book Service (информация о книгах)

    /api/authors/ → Author Service (информация об авторах)

Например, когда пользователь хочет создать новый заказ, он отправляет запрос POST /api/orders на Gateway. Gateway
анализирует путь /api/orders и перенаправляет запрос на Order Service. Order Service, в свою очередь, может обращаться к
Book Service для проверки наличия книг, а Book Service — к Author Service для получения информации об авторе. Но все эти
внутренние взаимодействия скрыты от клиента.

## Решение задачи аутентификации

Одна из ключевых задач, которую решает API Gateway в нашей архитектуре — централизация аутентификации. В текущей
реализации каждый защищенный endpoint должен проверять JWT-токен самостоятельно. Это приводит к дублированию кода и
потенциальным уязвимостям.
